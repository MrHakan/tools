How this encoder works

Input is split into the most compact mode it fits — numeric (3⅓ bits per digit), alphanumeric (5½ bits per character) or byte, with byte data encoded as UTF-8. The smallest of the 40 versions that holds the data at your chosen error-correction level is picked, the character-count indicator is sized for that version group, and the bit stream is padded with the standard 0xEC / 0x11 alternation. Error correction is Reed–Solomon over GF(256) with primitive polynomial 0x11D; the codewords are split into short and long blocks, each block gets its own remainder, and data and ECC bytes are interleaved. Finally all eight data masks are applied in turn, scored with the four penalty rules from the standard, and the lowest-scoring one is kept. Format information carries a BCH(15,5) code XORed with 0x5412; versions 7 and up also carry a BCH(18,6) version block.
